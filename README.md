# 影境拾遗 / PBZItemlist

《影之刃零》的浏览器本地存档查漏工具。选择自己的 `.sav` 文件，核对收集点位、铃铛和任务记录，再结合游戏地图投影或原生坐标继续探索。

## 在线使用

**[https://blog.kero.zone/](https://blog.kero.zone/)**

打开网页后选择自己的 `.sav` 文件即可，存档在浏览器本地解析，无需安装。

[使用指南](docs/USAGE.md) · [开发说明](docs/DEVELOPMENT.md) · [参与贡献](CONTRIBUTING.md)

当前目录包含 **13 类、698 个收集点位**，另有任务名称与分支目标说明。点位数量是本工具的数据口径，不等同于游戏内物品总数或地图完成度。

**1.1.0** 新增游戏地图投影，默认按游戏地图的方向和画布比例显示位置，并保留世界坐标切换。当前已为 646/698 个收集点和 175/187 个铃铛参照生成投影；未校准的点仍可从清单或世界坐标图查看。原生 XYZ、附近铃铛距离和 CSV 坐标保持原口径。重建方法与精度边界见[地图投影说明](docs/MAP-PROJECTION.md)。

## 能做什么

- 在浏览器中解码 **PBZS 3** 存档，支持自动与手动槽位，默认选择最近保存的可用槽位。
- 按地图、类别、名称或编号筛选，集中查看未完成与待确认点位。
- 切换游戏地图投影与世界 XY 图，查看原生 XYZ，以及附近铃铛的直线距离和开启状态。
- 查看完成依据与可核对条件；独立浏览任务状态、当前分支及已完成分支。
- 导出当前筛选结果为 CSV，或清空当前页面中的存档会话。

收集类别包含铃铛、黑石碎片、杀气琥珀碎片、记忆之花、钥匙、主要物品、武器、杀器、饰品、药品，以及龙柱、榕树和稻草人挑战。

## 存档如何处理

存档读取、解码与状态计算都在当前浏览器内完成。应用没有存档上传接口、账号系统、后端服务或存档持久化；不会写回或修改游戏存档。刷新页面或清空会话后，需要重新选择文件。

首次打开页面仍需下载站点本身的 HTML、JavaScript、图鉴数据和本地部署的 WebAssembly 解码器；这些资源请求不携带所选存档内容。

## 本地运行

运行站点只需 Python 3，无需安装 npm 依赖或执行构建：

```sh
git clone https://github.com/geturin/PBZItemlist.git
cd PBZItemlist
python -m http.server 8767 --bind 127.0.0.1 --directory public
```

打开 <http://localhost:8767/>。请通过 **HTTPS 或 localhost** 访问；直接双击 `index.html` 的 `file://` 方式不适用于模块加载与 WebCrypto。

浏览器需要支持 ES modules、WebCrypto、`DecompressionStream` 和 WebAssembly SIMD。格式不支持或文件校验失败时，页面会显示错误。

## 开发与测试

使用 Node.js **20 或更新版本**和 npm：

```sh
npm ci
npm test
```

默认测试依次执行图鉴校验、完成判定、地图绘图、合成存档解码和 DOM 仿真五步检查，不依赖个人存档。合成用例会调用真实 WASM 解码 Oodle stored frame，但不覆盖实际游戏中的 Mermaid 熵压缩流。用例数量以本次测试输出为准。

可使用环境变量 `PBZ_TEST_SAVE` 为 UI 增加真实存档回归；解码器与独立原生结果的比较则使用另一套可选目录参数。两种方式及其输入要求见[开发说明](docs/DEVELOPMENT.md#可选的真实存档检查)。仓库不附带真实存档或其解密 JSON。

DOM 仿真用于验证交互逻辑，不能代替真实浏览器的显示、布局和兼容性检查。

## 打包与部署

在项目根目录执行，需要 Python 3：

```sh
npm run package
```

也可直接执行 `python scripts/package.py`。输出为 `dist/PBZItemlist.zip`，ZIP 根目录即 `public/` 中的站点内容；将其解压到静态站点根目录，并通过 HTTPS 访问即可。打包流程不生成独立的源码 ZIP 或上游源码归档；完整项目源码及 ooz 对应源码保留在本仓库。

```text

  index.html            页面与界面说明

  js/app.js             本地导入、筛选、坐标图与交互
  js/map-view.js        游戏投影与世界坐标的独立绘图
  js/save-codec.js      PBZS 3 读取与校验
```

## 数据保留范围

仓库只保留运行工具所需的整理结果：名称、类别、地图、原生坐标、逐点地图投影、地图画布比例、完成判定标识、必要的事件关联，以及任务名称和分支目标。少量资源标识用于追溯某条判定的依据。

不包含游戏可执行文件、原始资源包、完整解包目录、原始投影锚点或网格、地图贴图、整份脚本或本地化转储，也不包含个人存档、解密后的私人进度、调查临时文件或服务器凭据。`vendor/ooz-wasm/` 中的开源解码器及其对应源码属于应用运行与许可证履行所需内容。

## 判断结果的边界

- **两种位置图都不提供道路导航。** 游戏模式用离线重建的锚点网格投影，尚未与运行中的游戏逐点比对；共圆点和边界细节可能有差异，游戏自身的图标避让也会移动标记。高差、门锁、洞口、升降机和任务进度都会影响可达性；最近铃铛仍按原生坐标的直线距离计算。
- **任务关联不等于领取前置。** 任务日志展示存档中的状态；没有还原实际前置逻辑时，不会据此制造确定的物品条件。任务失败也不代表所有相关物品一定永久错过。
- **待确认不等于未获得。** 旧版本、缺失记录和部分钥匙的已用状态，可能不足以支持明确结论。
- **槽位与周目分别判断。** 自动存档和手动存档可能属于不同进度；某些装备按本周目的获得记录核对，其他周目拥有过也可能显示本周目未完成。
- **点位统计不等于游戏完成度。** 同一物品可能有多个来源，记忆之花存在父项与花瓣关系，部分地图定义的当前可达性也仍需核对。钥匙和主要物品不应直接计入游戏的收集总百分比。
- 格式与图鉴有版本范围。当前支持 PBZS 3；后续游戏更新可能改变结构、编号或记录方式。

本工具为非官方项目。遇到不一致时，可先查看记录详情中的依据，再对照游戏内状态；反馈方法见[贡献指南](CONTRIBUTING.md)。
