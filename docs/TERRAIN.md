# 地图贴图与楼层示意

2.1 默认使用游戏原生美术地图，收集点按游戏 UV 显示。楼层平面和 Three.js 3D 是可选的定位示意，独立加载；它们不是完整游戏场景。所有视图均保留收集点原始 XYZ，不改变完成判定、铃铛距离或 CSV 坐标。

## 默认地图：轻量游戏贴图

默认地图直接读取图鉴中的图像引用和点位 UV，不请求楼层几何，也不请求 `terrain-low/manifest.json`。

| 图像级别 | 加载时机 | 8 张共用图像合计 |
| --- | --- | ---: |
| 1024 像素预览 | 选择对应地图后 | 777,384 字节 |
| 2048 像素细节 | 当前地图放大到 2 倍及以上时 | 3,351,358 字节 |

每张预览约 100 KB；多张逻辑地图可共用一张美术贴图。细节图按当前地图需要加载，不在打开页面时一次下载全部图像。降低图像分辨率不改变贴图比例或归一化 UV，也不改变点位坐标。

图像位于 `public/data/map-images/`，绑定记录在 `catalog.json` 的地图条目中。上述字节数是图像文件的网络体积，不是浏览器内存上限；图像解码后的位图和绘图画布仍占用内存。

## 可选的 2D 与 3D 楼层示意

楼层数据由游戏导航地面整理而来，按 **5 米高度层**提取并清理轮廓。2D 使用预处理平面轮廓；3D 使用这些轮廓形成的简化楼层平面，保留不同高度的位置关系。它们不在页面主线程重新处理整套高密度导航三角形。

这是显示近似：细小碎片、狭缝和轮廓经过清理与简化，楼层面使用代表高度。它不保留原始导航面的全部细节，也不保证台阶、斜坡、洞口或局部连接逐点一致。不能把它当成完整环境模型或当前存档下的通行判定。

发布清单为 `public/data/terrain-low/manifest.json`；2D 和 3D 分别有独立文件、内容哈希和计数。实际发布规模以该清单为准。旧版高密度导航派生网格仍保留在源码 `public/data/terrain/` 供回归比较；当前页面不请求该目录，发布 ZIP 排除它。旧版体积和面数不代表当前站点下载量。

当前发布覆盖 **9 个来源世界、12 个原生地图分区**，合计 458 个高度切片：

| 资产 | 当前规模 | gzip 合计 |
| --- | --- | ---: |
| 独立 2D 轮廓 | 255,257 个轮廓点，含闭合点 | 1,128,873 字节 |
| 3D 楼层平面 | 224,473 个顶点、202,798 个三角形 | 1,962,099 字节 |

单个世界 3D 文件最大为 374,856 字节。3D gzip 相比旧版 20,668,223 字节减少 90.5%，三角形数减少 88.6%。这些是发布文件体积与计数，不代表浏览器内存或帧率实测。

| 数据 | 浏览器中的用途 |
| --- | --- |
| 2D 轮廓，`format: 2` | `layers` 的高度范围、分区和多边形环；Canvas 按外轮廓与洞填充，不遍历 3D 三角形 |
| 3D 楼层，`format: 1` | 厘米世界坐标、三角索引、`zBands` 与取景元数据；由 Worker 解压解析后转移 typed buffer |
| `mapFocus` / `focusByBand` | 逻辑地图及高度区域的初始取景提示，不是精确区域边界 |

## 按需加载与内存

```text
默认游戏地图
  → catalog 中的图像引用与 UV
  → 当前地图 1024 预览
  → 放大到 2 倍时才读取当前地图 2048 细节

可选 2D 楼层
  → 独立轮廓文件
  → Canvas / Path2D 缓存

可选 3D 楼层
  → 先选中物品；未选中时不下载模型或启动 WebGL
  → 独立 3D 文件
  → Worker 内解压、校验、JSON 解析和 typed array 转换
  → 转移 Float64 XYZ 与 Uint32 索引 buffer
  → Three.js 低模表面与物品标记
```

切换地图或模式时取消不再需要的请求，释放对应缓存。离开 3D 会暂停绘制、清除几何与标记引用，并释放 GPU 几何；隐藏画布缩到 1×1。重新进入时按需加载。实际内存回收时间还受浏览器控制。

3D 同一世界切换取景或筛选时复用 GPU 几何和同键标记。默认不生成裙边，不绘制额外线框，不启用 MSAA，设备像素比最高 1.5；只在操作或数据变化后请求绘制，不维持空闲动画循环。

Three.js 与 OrbitControls 只在 3D 已有选中物品后初始化，从本站固定版本目录加载。单纯切到 3D 而未选物品，不会下载模型或启动 WebGL。WebGL2 不可用或初始化失败时返回原生游戏地图，不影响存档处理。

## 3D 操作

- 默认左键或单指拖动平移，右键拖动旋转；滚轮、双指和 `+` / `−` 按钮缩放。
- “平移 / 旋转”切换左键和单指的操作方式，键盘 `Home` 或“复位”恢复取景。
- 首次显示物品时自动靠近一次，并默认勾选高度聚焦，只显示其原始 Z 上下各 250 厘米。
- 后续选中物品保持当前缩放，只移动观察目标；“靠近选中”可再次主动拉近。
- 取消高度聚焦可查看区域概览；默认不把整个世界的多层平面堆叠展示。高度过滤不删除收集清单条目。

## 坐标与精度

离线读取导航数据时，轴转换为：

```text
Unreal (X,Y,Z) = (-RecastX,-RecastZ,RecastY)
```

显示资产已经使用 Unreal XYZ 厘米，浏览器不应再次执行该转换。3D 先减去双精度原点，再生成 GPU 所需的 Float32 米制坐标：

```text
Three = ((X-originX)/100, (Z-originZ)/100, -(Y-originY)/100)
```

物品标记保留自己的原始高度，不吸附到另一层。楼层显示数据的代表高度与轮廓近似不会写回物品坐标。

杀气塔三处铃铛的定点高度核验不能代表全部拾取点都紧贴楼层面；源导航覆盖与显示近似均有边界。

游戏贴图采用游戏 UV；楼层平面使用世界 XY，两者不要求轮廓或朝向逐像素重合。UV 的离线重建与游戏图标避让边界见[地图投影说明](MAP-PROJECTION.md)。

## 场景与数据边界

游戏安装资源中存在 HLOD 等场景资产，但本项目尚无可验证的完整游戏场景导出；它们不是当前网页的显示数据。网页没有导出或加载完整建筑、植被、材质、光照与场景模型。

站点只分发所需的地图预览、细节图和楼层示意，不分发原始 Unreal 包、完整贴图集、完整导航转储、原始投影锚点或私人调查文件。游戏名称和美术内容的权利归各自权利人所有。

本工具不计算路线。游戏的动态门锁、任务条件、跳跃和入口限制不能由这些示意图确定；附近铃铛的直线距离也不代表可步行距离。
